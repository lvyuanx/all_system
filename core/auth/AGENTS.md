# core.auth

## 模块定位
- `core.auth` 是核心认证与用户体系模块。
- 它属于 `core` 框架层的一部分，负责账号、登录、权限相关基础能力。
- 这里的能力应尽量保持通用，不要掺入具体业务模块语义。

## 目录说明
- `models.py`：用户、认证相关模型
- `views/`：API 视图实现
- `apis.py` / `mobile_apis.py`：后台与移动端接口注册
- `admin.py`：后台管理配置
- `backends.py`：认证后端
- `signals/`：认证相关信号

## 通用约定
- 在 Django template 中使用 Vue 时，统一沿用 `[[ ]]` 作为插值分隔符，避免和 Django 的 `{{ }}` 冲突。
- 单个文件尽量不要超过 `500` 行；如果明显超出，应优先按职责拆分。

## 修改约束
- 优先保持认证协议、JWT/登录态语义、权限判断方式不变。
- 如果需求带明显业务属性，应放到业务 app，不要回写到 `core.auth`。
- API 层优先沿用 `core.ninja_extra.BaseApi` 模式。

## 验证建议
- 认证相关改动优先检查：
  - 后台登录
  - 移动端登录
  - 当前用户信息
  - 权限菜单/权限包相关接口
