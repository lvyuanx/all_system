# order

## 模块定位
- `order` 是订单管理核心业务模块。
- 同时承担后台订单管理和移动端订单 API。

## 目录说明
- `models.py`：订单核心模型
- `views/`：订单 API 与子领域逻辑
- `page_views/`：后台页面
- `mobile_apis.py`：移动端订单接口入口
- `machine.py`：订单状态流转相关逻辑
- `templates/`：订单后台模板

## 通用约定
- 在 Django template 中使用 Vue 时，统一沿用 `[[ ]]` 作为插值分隔符，避免和 Django 的 `{{ }}` 冲突。
- 单个文件尽量不要超过 `500` 行；如果明显超出，应优先按职责拆分。

## 后台订单页面权限与状态设计
- 订单后台不是每个菜单都对应一套完全独立页面；左侧菜单中的“所有订单 / 订单池 / 待排产 / 待生产 / 生产中 / 待发货 / 待签收 / 已完成 / 已取消”等入口，本质上主要通过同一个 `OrderAdmin` 列表页叠加 `order_status` 筛选、菜单权限和页面元素显隐，组合出不同工作台效果。
- 订单 Admin 的页面能力应同时看两个维度：
  - 当前菜单入口或 URL 查询参数传入的订单状态，例如 `order_status=10/20/30/40/50/60/70/0`
  - 当前登录用户是否拥有对应业务权限，以及是否是订单创建人、确认人、`superuser`
- 不要只根据“用户能进入菜单”推断其能执行页面上的所有操作。菜单权限用于控制入口可见性；列表按钮、批量操作、字段/筛选项、弹窗入口仍要结合订单状态和用户权限二次判断。
- `OrderAdmin.get_status_by_request()` 是后台列表识别当前状态视图的重要入口；新增或调整订单菜单状态筛选时，要同步检查 `has_add_permission()`、`get_list_filter()`、`get_actions()`、`get_operate_buttons_config()` 等基于状态控制页面元素的方法。
- 行操作按钮采用 `OperateButtonsMixin` + `get_operate_buttons_config()` 动态生成，典型规则包括：
  - `确认`：仅在订单为“已创建”且当前用户满足确认权限/确认人规则时显示。
  - `取消`：仅在订单未排产前，并且当前用户满足创建人/确认人等取消规则时显示。
  - `流程`、`流程数据`、`生产完成`：与生产状态、是否绑定流程定义共同决定显隐。
  - `发货`、`支付`、`操作日志`等入口也要保持与订单状态和业务链路一致，不要改成无条件展示。
- 批量操作不是固定按钮集合，`get_actions()` 会按当前 `order_status` 入口隐藏不适合的操作，例如“待排产”显示排产，“待生产”显示生产，“待签收”显示签收。新增批量动作时要按状态入口做同类控制。
- 关键权限判断应优先复用 `order.services` 中的共享规则，例如 `can_order_confirm()`、`ensure_order_confirm_user()`、`ensure_order_cancel_user()`、`ensure_order_cancel_memo()`，避免在模板或 Admin 中复制一份容易漂移的判断。
- 页面显隐只是用户体验层，真正执行动作的 Admin view / API / 状态机仍必须再次校验状态和权限。不能只靠前端隐藏按钮保证安全。
- `main/init/init_menus_perm.py` 维护了订单菜单与权限的基础映射，例如“订单池”对应创建/确认，“待排产”对应排产，“待生产/生产中”对应生产，“待发货”对应发货，“待签收”对应签收，“已取消”对应取消。调整菜单或权限时要同步检查这里。
- `superuser` 默认拥有最高权限；除非需求明确排除，订单后台权限显隐和动作执行都应让 `superuser` 可操作。

## 修改约束
- 订单状态机、支付、发货、生产等流程改动要谨慎。
- 这是移动端接口的重要来源模块，改 API 时要同时考虑后台和移动端影响。
- 尽量不要让 `order` 依赖过多其他业务模块内部实现。
- 修改订单 Admin 页面元素显隐时，应同时检查列表入口、行按钮、批量操作、服务层权限校验和最终执行视图/API，保持“状态 + 权限”规则一致。

## 验证建议
- 重点检查：
  - 订单后台列表/详情
  - 订单状态流转
  - 移动端订单接口
  - 支付、发货、生产相关链路
- 涉及后台订单菜单、按钮显隐、批量操作、弹窗或状态筛选时，优先用浏览器实测对应菜单入口，而不是只看代码判断。
