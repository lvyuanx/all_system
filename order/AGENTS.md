# order

## 模块定位
- `order` 是订单管理核心业务模块。
- 同时承担后台订单管理和移动端订单 API。

## 目录说明
- `models.py`：订单核心模型
- `views/`：订单 API 与子领域逻辑
- `page_views/`：后台页面
- `mobile_apis.py`：移动端订单接口入口
- `machine.py`：订单状态流转相关逻辑
- `templates/`：订单后台模板

## 通用约定
- 在 Django template 中使用 Vue 时，统一沿用 `[[ ]]` 作为插值分隔符，避免和 Django 的 `{{ }}` 冲突。
- 单个文件尽量不要超过 `500` 行；如果明显超出，应优先按职责拆分。

## 修改约束
- 订单状态机、支付、发货、生产等流程改动要谨慎。
- 这是移动端接口的重要来源模块，改 API 时要同时考虑后台和移动端影响。
- 尽量不要让 `order` 依赖过多其他业务模块内部实现。

## 验证建议
- 重点检查：
  - 订单后台列表/详情
  - 订单状态流转
  - 移动端订单接口
  - 支付、发货、生产相关链路
