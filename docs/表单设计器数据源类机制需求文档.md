# 表单设计器数据源类机制需求文档

## 1. 文档信息

- 文档名称：表单设计器数据源类机制需求文档
- 文档版本：v1.0
- 创建日期：2026-04-10
- 适用范围：`flow_engine/templates/flow_engine/form_designer.html` 及相关运行时解析逻辑
- 文档目标：统一字段默认值和选项值的获取方式，建立“固定值 + 数据源类”的扩展机制

## 2. 背景

当前表单设计器中的字段默认值、选项值获取方式偏前端配置化，存在以下问题：

- 配置项分散，字段上直接堆积 `default_config`、`options_config`、上下文路径等细粒度设置，设计器交互复杂。
- 数据获取逻辑主要靠前端结构约定，缺少统一抽象，不利于后续扩展更多业务数据来源。
- 流程上下文读取能力不统一，字段逻辑难以复用。
- 当业务侧需要新增一种默认值或选项来源时，往往需要同时改前端配置、后端解析、字段协议，维护成本高。

为了提升可扩展性、可维护性和业务接入效率，需要将字段默认值与选项的获取逻辑收敛为统一的数据源机制。

## 3. 目标

本期目标：

- 将字段数据获取方式统一收敛为两种：
  - 固定值
  - 数据源类
- 数据源类必须继承统一的数据源基类。
- 数据源类通过类属性声明其支持的数据类型和能力。
- 数据源类通过 `self.ctx` 获取当前流程完整上下文。
- 数据源类的方法只接收一个 `request` 参数，避免方法签名膨胀。
- 数据源类统一注册在 `flow_engine` 配置中，设计器可读取注册结果供用户选择。
- 设计器不再直接暴露底层“数据库/枚举/上下文路径”等零散配置，而是让用户直接选择数据源类。

## 4. 非目标

本期不做以下内容：

- 不实现任意 Python 表达式脚本型数据源。
- 不开放前端直接输入 Python 路径动态加载类。
- 不允许数据源类直接写回流程上下文。
- 不改变当前表单提交流程对上下文写入的主机制。
- 不在本期做自动批量迁移所有历史表单配置，只保留兼容读取能力。

## 5. 核心概念

### 5.1 字段组件 component

字段组件用于描述前端展示形态，例如：

- `input`
- `textarea`
- `number`
- `radio`
- `checkbox`
- `select`
- `switch`
- `date`
- `datetime`
- `file`

组件解决的是“字段怎么展示”。

### 5.2 数据源类型 data_type

`data_type` 用于描述数据源返回的数据语义，而不是前端控件类型。

建议支持以下类型：

- `text`
- `number`
- `boolean`
- `radio`
- `checkbox`
- `select`
- `date`
- `datetime`
- `file`

说明：

- `input` 和 `textarea` 都归属于 `text`
- `switch` 归属于 `boolean`
- `radio`、`checkbox`、`select` 单独保留，因为它们不仅值结构不同，选项组织方式也不同

### 5.3 support_components

为了让同一个 `data_type` 能精准约束适用字段组件，需要增加 `support_components`。

例如：

- 文本型数据源：
  - `data_type = "text"`
  - `support_components = ["input", "textarea"]`

- 布尔型数据源：
  - `data_type = "boolean"`
  - `support_components = ["switch"]`

这样，设计器能根据组件过滤出可用数据源类。

### 5.4 数据源能力

数据源类不一定同时负责默认值和选项列表，因此建议增加能力标记：

- `support_default`
- `support_options`

示例：

- 文本默认值数据源：只支持 `support_default = True`
- 下拉选项数据源：只支持 `support_options = True`
- 某些复杂数据源：可同时支持 `default + options`

## 6. 需求概述

### 6.1 字段数据获取方式

每个字段的数据获取方式统一为：

- 固定值
- 数据源类

其中：

- 固定值：由设计器直接配置字面值
- 数据源类：由后端已注册的数据源类在运行时动态计算返回

### 6.2 数据源类的要求

数据源类必须满足：

- 继承统一数据源基类
- 声明 `key`
- 声明 `label`
- 声明 `data_type`
- 声明 `support_components`
- 声明 `support_default` / `support_options`
- 可选声明 `params_schema`
- 实现对应方法：
  - `get_default(request)`
  - `get_options(request)`

### 6.3 流程上下文获取

数据源类内部必须能够通过 `self.ctx` 获取当前流程上下文。

要求：

- `self.ctx` 为当前流程实例完整上下文
- `self.ctx` 在运行时由引擎统一注入
- 数据源类方法只接收 `request` 作为唯一入参
- 数据源类内部可通过实例属性获取运行时环境，而不是通过方法签名传多个参数

### 6.4 注册机制

数据源类不通过前端自由输入，而是统一注册到 `flow_engine` 配置文件中。

设计器加载时从后端获取注册数据源元信息，供用户选择。

## 7. 详细设计

### 7.1 数据源基类设计

建议新增统一基类，例如：

`flow_engine/data_sources/base.py`

建议基类定义如下：

```python
class BaseFieldDataSource:
    key = ""
    label = ""
    data_type = ""
    support_components = []
    support_default = False
    support_options = False
    params_schema = []

    def __init__(self):
        self.ctx = {}
        self.request = None
        self.field_schema = {}
        self.instance = None
        self.node_code = ""

    def bind_runtime(self, *, ctx, request, field_schema, instance, node_code):
        self.ctx = ctx or {}
        self.request = request
        self.field_schema = field_schema or {}
        self.instance = instance
        self.node_code = node_code or ""
        return self

    def validate_config(self):
        return True

    def get_default(self, request):
        raise NotImplementedError

    def get_options(self, request):
        raise NotImplementedError
```

### 7.2 基类属性说明

- `key`
  - 数据源唯一标识
  - 用于 schema 和配置文件中引用
  - 不建议直接依赖类名

- `label`
  - 设计器中展示名称

- `data_type`
  - 该数据源返回的数据语义类型

- `support_components`
  - 该数据源支持的字段组件列表

- `support_default`
  - 是否支持默认值获取

- `support_options`
  - 是否支持选项列表获取

- `params_schema`
  - 用于描述该数据源类所需的参数结构，供前端动态渲染配置表单

### 7.3 运行时实例属性说明

运行时注入的实例属性建议包含：

- `self.ctx`
  - 当前流程上下文

- `self.request`
  - 当前请求对象

- `self.field_schema`
  - 当前字段完整 schema

- `self.instance`
  - 当前流程实例

- `self.node_code`
  - 当前节点编码

### 7.4 数据源返回规范

#### 默认值

`get_default(request)` 返回：

- 文本型：字符串
- 数字型：数字
- 布尔型：布尔值
- 单选/下拉型：单个值
- 多选型：数组
- 日期型：日期字符串
- 文件型：文件标识或文件列表

#### 选项列表

`get_options(request)` 返回统一结构：

```python
[
    {"label": "选项1", "value": "v1"},
    {"label": "选项2", "value": "v2"},
]
```

对于 `checkbox` 类型，返回仍然是选项数组，字段值本身在运行时是多值数组。

### 7.5 参数 schema 设计

建议每个数据源类可声明参数结构：

```python
params_schema = [
    {
        "key": "context_path",
        "label": "上下文路径",
        "type": "text",
        "required": True,
        "placeholder": "如: form.NODE_A.amount",
    }
]
```

建议支持的参数类型：

- `text`
- `number`
- `boolean`
- `select`
- `textarea`
- `json`
- `context_path`

前端可根据 `params_schema` 自动渲染参数表单，无需为每个数据源类单独写 UI。

### 7.6 注册配置设计

建议在 `flow_engine` 配置中新增：

```python
FLOW_ENGINE_FIELD_DATA_SOURCES = [
    "flow_engine.data_sources.ctx.TextContextDataSource",
    "flow_engine.data_sources.order.OrderFieldTextDataSource",
    "flow_engine.data_sources.options.StaticSelectOptionsDataSource",
]
```

注册中心负责：

- 加载配置列表
- 导入类
- 校验是否继承基类
- 校验 `key` 唯一
- 校验 `data_type` 合法
- 校验 `support_components` 合法

### 7.7 注册中心设计

建议新增：

`flow_engine/data_sources/registry.py`

提供以下能力：

- `load_all_sources()`
- `get_source_meta_list()`
- `get_source_class(key)`
- `build_source(key)`
- `validate_source_class(cls)`

### 7.8 字段配置结构设计

建议将字段数据获取改为统一配置结构。

#### 默认值配置

```json
{
  "mode": "fixed",
  "value": "默认文本"
}
```

或：

```json
{
  "mode": "data_source",
  "source_key": "ctx_text",
  "source_params": {
    "context_path": "form.NODE_A.reason"
  },
  "fallback_value": ""
}
```

#### 选项配置

```json
{
  "mode": "data_source",
  "source_key": "site_address_select",
  "source_params": {
    "site_path": "site_id"
  }
}
```

建议字段中拆分为两段：

- `default_source_config`
- `options_source_config`

理由：

- 默认值和选项列表职责不同
- 一个字段可能同时需要“固定默认值 + 动态选项”
- 拆开后可避免一个配置结构承担过多语义

### 7.9 前端设计器交互设计

在字段配置区域中：

#### 默认值区域

- 获取方式：
  - 固定值
  - 数据源类
- 当选择固定值时：
  - 展示一个固定值输入框
- 当选择数据源类时：
  - 展示数据源类下拉框
  - 展示参数配置区
  - 展示回退值输入框

#### 选项来源区域

仅当组件为：

- `radio`
- `checkbox`
- `select`

才显示。

选项来源同样支持：

- 固定选项
- 数据源类

### 7.10 前端过滤规则

设计器展示可选数据源类时，需要根据字段组件做过滤：

- 字段组件 `textarea`
  - 只展示 `support_components` 中包含 `textarea` 的数据源类

- 字段组件 `switch`
  - 只展示 `support_components` 中包含 `switch` 的布尔型数据源

- 字段组件 `checkbox`
  - 默认值数据源和选项数据源都要校验兼容性

### 7.11 运行时解析流程

运行时加载表单时，流程如下：

1. 读取当前字段 schema
2. 判断默认值模式：
   - 固定值：直接返回
   - 数据源类：通过注册中心实例化数据源类
3. 为数据源实例注入运行时上下文
4. 调用 `get_default(request)` 获取默认值
5. 若字段为选项型组件，再解析 `options_source_config`
6. 调用 `get_options(request)` 获取选项列表
7. 若执行失败，则根据回退策略处理

### 7.12 上下文写回规则

本期数据源类只负责读取，不负责写入。

表单提交后：

- 仍由原有字段上下文绑定机制负责写回
- 数据源类只通过 `self.ctx` 读取流程上下文
- 数据源类不能直接修改 `self.ctx`

### 7.13 异常处理策略

当数据源执行失败时：

- 默认记录错误日志
- 页面不崩溃
- 默认值型数据源：
  - 优先使用 `fallback_value`
  - 否则使用空值
- 选项型数据源：
  - 默认使用空选项列表
  - 可选支持回退到手工选项

### 7.14 错误提示规范

提示全部使用中文，示例：

- 未找到数据源类
- 数据源类未继承基类
- 数据源类型与字段组件不匹配
- 数据源参数缺失
- 数据源执行失败
- 返回数据结构不合法

## 8. 示例数据源类

### 8.1 上下文文本默认值数据源

```python
class ContextTextDataSource(BaseFieldDataSource):
    key = "ctx_text"
    label = "流程上下文文本"
    data_type = "text"
    support_components = ["input", "textarea"]
    support_default = True
    support_options = False
    params_schema = [
        {
            "key": "context_path",
            "label": "上下文路径",
            "type": "text",
            "required": True,
        }
    ]

    def get_default(self, request):
        path = self.field_schema.get("default_source_config", {}).get("source_params", {}).get("context_path")
        return self.ctx.get(path)
```

### 8.2 订单字段文本数据源

```python
class OrderFieldTextDataSource(BaseFieldDataSource):
    key = "order_field_text"
    label = "订单字段文本"
    data_type = "text"
    support_components = ["input", "textarea"]
    support_default = True
```

### 8.3 站点地址下拉选项数据源

```python
class SiteAddressSelectDataSource(BaseFieldDataSource):
    key = "site_address_select"
    label = "站点地址下拉选项"
    data_type = "select"
    support_components = ["select"]
    support_default = False
    support_options = True
```

现有运行时解析逻辑改造后继续输出：

- 字段 schema
- 默认值
- 选项列表

但字段值来源从旧 `default_config/options_config` 转为数据源类。

## 10. 兼容性设计

### 10.1 历史配置兼容

历史字段若仍包含：

- `default_config`
- `options_config`
- `context_binding`

则运行时继续兼容解析。

### 10.2 新旧配置优先级

建议优先级：

1. 新配置 `default_source_config/options_source_config`
2. 旧配置 `default_config/options_config`
3. 固定字段值 `default/options`

### 10.3 迁移策略

本期不强制批量迁移旧数据，仅支持：

- 旧流程可运行
- 新流程按新结构保存
- 后续视情况补迁移脚本

## 11. 风险点

- 数据源类设计过于自由会造成业务代码碎片化
- 若不限制 `support_components`，前端过滤会混乱
- 若不统一参数 schema，前端设计器无法优雅扩展
- 若数据源类允许写上下文，会导致运行时行为不可控
- 若错误提示不统一，排查成本会提高

## 12. 验收标准

- 设计器中字段默认值获取方式仅显示：
  - 固定值
  - 数据源类
- 用户可在设计器中选择已注册的数据源类
- 字段组件切换后，可选数据源类会正确过滤
- 数据源类运行时能通过 `self.ctx` 访问流程上下文
- 数据源类方法入参仅为 `request`
- 默认值和选项列表可通过数据源类正确获取
- 数据源执行失败时页面不崩溃，且提示为中文
- 历史表单配置仍能正常运行
